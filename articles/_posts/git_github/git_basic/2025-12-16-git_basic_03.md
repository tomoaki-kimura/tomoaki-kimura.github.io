### ブランチとは

ブランチは、同じリポジトリの中で作業の流れを分岐させる仕組みです。今の履歴はそのままにしておいて、別のブランチで新しい機能を試し、うまくいったら元のブランチに合流（マージ）する、という使い方をします。

今いるブランチは `git branch` で確認できます。

```bash
sample_app $ git branch
* main
```

`*` がついているのが今いるブランチです。`git init` した直後は `main` というブランチにいます。

### 新しいブランチを作って移動する

新しいブランチを作って、そこに移動するには `git switch -c` を使います。

```bash
sample_app $ git switch -c feature
Switched to a new branch 'feature'
```

`-c` は「新しく作る（create）」という意味です。`git branch` で確認すると、`feature` に移っていることが分かります。

```bash
sample_app $ git branch
* feature
  main
```

### featureブランチで変更してコミットする

このブランチで `main.rb` を変更してコミットしてみましょう。

```bash
sample_app $ echo "puts 'hello'" >> main.rb
sample_app $ git add main.rb
sample_app $ git commit -m "hello出力を追加"
```

### mainブランチに戻る

`git switch` に `-c` をつけずに使うと、既存のブランチに移動できます。

```bash
sample_app $ git switch main
Switched to branch 'main'
```

`main.rb` の中身を見ると、`feature` ブランチでの変更は反映されていません。ブランチごとに独立して履歴が進むためです。

### マージする

`feature` ブランチの変更を `main` に取り込むには `git merge` を使います。`main` ブランチにいる状態で実行します。

```bash
sample_app $ git merge feature
Updating d67f585..xxxxxxx
Fast-forward
 main.rb | 1 +
 1 file changed, 1 insertion(+)
```

これで `main.rb` に `feature` での変更が反映されます。

#### *ここで試したいこと

- `git switch -c` でもう1つ別のブランチを作り、`git branch` で複数のブランチが並んでいることを確認してみよう。
