## {{ page.section_title }}

### git add でステージに載せる

前回作った `main.rb` の変更を記録するために、まず `git add` で「次に記録する変更」として選びます。

```bash
sample_app $ git add main.rb
```

もう一度 `git status` を見てみましょう。

```bash
sample_app $ git status
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
	new file:   main.rb
```

`Changes to be committed` に表示されるようになりました。これを「ステージに載っている」状態と呼びます。まだ記録は完了していません。

### git commit で記録する

`git commit` で、ステージに載っている変更を実際に記録します。`-m` のあとにこの変更内容の説明（コミットメッセージ）を書きます。

```bash
sample_app $ git commit -m "main.rbを作成"
[main (root-commit) d67f585] main.rbを作成
 1 file changed, 0 insertions(+), 0 deletions(-)
 create mode 100644 main.rb
```

これで、この変更が記録（コミット）されました。1回のコミットが、履歴の1つの区切りになります。

### git log で履歴を見る

これまでのコミットの履歴は `git log` で確認できます。

```bash
sample_app $ git log
commit d67f585...
Author: あなたの名前 <you@example.com>
Date:   ...

    main.rbを作成
```

1行で簡潔に見たいときは `--oneline` をつけます。

```bash
sample_app $ git log --oneline
d67f585 main.rbを作成
```

### add → commit の流れ

ここまでの流れをまとめると、以下のようになります。

1. ファイルを編集する
2. `git add` で、記録したい変更をステージに載せる
3. `git commit -m "説明"` で、ステージの内容を記録する

以降、ファイルを変更するたびにこの流れをくり返していきます。

#### *ここで試したいこと

- `main.rb` の中身を変更してから、もう一度 `git status` → `git add` → `git commit` の流れを試し、`git log --oneline` にコミットが増えることを確認してみよう。
