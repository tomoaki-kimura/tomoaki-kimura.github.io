## {{ page.section_title }}

### LLM は会話を覚えていない

前のセクションで試した通り、LLM は前の質問を覚えていません。API は1回ずつ独立していて、送られてきた `messages` だけを見て回答しています。

そこで、アプリ側で会話の履歴を配列に貯めておき、毎回 **履歴をまるごと** 送るようにします。ChatGPT のようなサービスも、基本は同じ仕組みです。

### 履歴を貯める

app.rb

```ruby
(略)
MODEL = "qwen2.5:3b"

# 会話の履歴
HISTORY = []

# LLMに会話を送り、回答の文章を返す
def ask(messages)
(略)
end

get "/" do
  erb :index
end

post "/chat" do
  HISTORY << { role: "user", content: params[:question] }
  answer = ask(HISTORY)
  HISTORY << { role: "assistant", content: answer }
  redirect "/"
end
```

`role: "assistant"` は「LLM の発言」という意味です。

`HISTORY` はアプリ全体で1つだけの配列なので、誰がアクセスしても同じ履歴になります。自分のパソコンで1人で使う練習用として、このまま進めます。

### 履歴を表示する

views/index.erb

```erb
(略)
<body>
  <h1>ローカルLLMチャット</h1>
  <% HISTORY.each do |message| %>
    <p>
      <strong><%= message[:role] == "user" ? "あなた" : "AI" %>：</strong>
      <%= Rack::Utils.escape_html(message[:content]).gsub("\n", "<br>") %>
    </p>
  <% end %>
  <form action="/chat" method="post">
    <textarea name="question" rows="3" cols="50"></textarea>
    <button type="submit">送信</button>
  </form>
</body>
</html>
```

会話が上から順に並ぶように、フォームを一番下に移動しています。

### ファイルの実行

Sinatra は `app.rb` を変更したら再起動が必要です。`Ctrl + C` で止めてから、もう一度起動します。

bash
```
llm_chat $ ruby app.rb
```

### 結果

会話が画面に積み重なり、「さっき何を聞いた？」にも答えられるようになる。

#### *ここで試したいこと

- 会話を長く続けると、回答が返ってくるまでの時間がどう変わるか確認する。
- `ruby app.rb` を再起動すると、履歴がどうなるか確認する。
