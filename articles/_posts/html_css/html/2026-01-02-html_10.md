### アクセシビリティとは

アクセシビリティとは、目が見えない・見えにくい方や、マウスがうまく使えない方など、さまざまな人がWebページを問題なく利用できるようにすることです。特に、画面を読み上げる「スクリーンリーダー」というソフトを使っている方にとって、HTMLの書き方は非常に重要です。ここまでの内容を、アクセシビリティの観点で振り返ります。

### 1. 見出しの階層を守る（第3回）

スクリーンリーダーには、見出しだけを一覧して読み上げ、ページの構造を素早く把握する機能があります。`<h1>`から順番に、階層を飛ばさずに使うことが大切でした。

### 2. 意味のあるタグを使う（第4回）

`<header>` `<nav>` `<main>` のようなタグを使うと、スクリーンリーダーは「今はナビゲーションの中にいる」「ここからが本文だ」と伝えることができます。すべてを`<div>`で書いてしまうと、この情報が失われます。

### 3. altテキストを書く（第6回）

画像の`alt`は、目が見えないユーザーにとってその画像の唯一の情報源でした。装飾目的の画像は`alt=""`にして読み上げをスキップさせる、という使い分けも学びました。

### 4. tableは表データにだけ使う（第7回）

`<table>`を使うと、スクリーンリーダーは「表である」と認識して読み上げ方を変えます。レイアウト目的で使わない、というのはアクセシビリティの観点からも重要でした。

### 5. labelとinputを紐付ける（第8回）

`for`と`id`が対応していないと、スクリーンリーダーは入力欄が何を入力する欄なのか伝えられません。フォームでは特に重要なポイントです。

### aria属性という選択肢もある

HTMLの標準タグだけでは意味を伝えきれない場合、`aria-*`という特別な属性を補助的に使うこともできます。例えば、見た目はボタンだが`<button>`タグが使えない事情があるとき、`role="button"`を指定したり、アイコンだけのボタンに`aria-label="メニューを開く"`を指定して読み上げ用のテキストを補ったりします。

```html
<button aria-label="メニューを開く">
  ☰
</button>
```

ただし、`aria-*`は「正しいHTMLタグが使えないときの最後の手段」という位置づけです。まずは今回学んだ意味のあるタグ（`<nav>`や`<button>`など）を正しく使うことが優先で、aria属性はその補助、と覚えておきましょう。
