### 古いやり方：ページ・パーツごとにidを振る

CSSがまだ発展途上だった頃は、ページやパーツごとに個別の`id`を振って、それぞれに1つずつスタイルを書く方法がよく使われていました。

```html
<div id="about-section">...</div>
<div id="service-section">...</div>
```

```css
#about-section {
  padding: 40px;
  background-color: #f5f5f5;
}
#service-section {
  padding: 40px;
  background-color: #f5f5f5;
}
```

この書き方だと、同じ`padding`や`background-color`を持つ場所が増えるたびに、ほぼ同じCSSを何度も書くことになります。修正のときも、全部の場所を1つずつ直す必要があり大変です。

### 汎用的なクラスを使う考え方

そこで、「見た目のパターン」を1つのclassにまとめて、必要な場所にそのclassをつけて回る、という考え方が広まりました。

```html
<div class="section-block">...</div>
<div class="section-block">...</div>
```

```css
.section-block {
  padding: 40px;
  background-color: #f5f5f5;
}
```

この`.section-block`のように、意味的な内容ではなく「見た目のパターン」を表す、使い回し前提のclassをたくさん用意しておく考え方は、この後の回で学ぶBootstrapのようなCSSフレームワークの基本的な思想でもあります（Bootstrapという名前はまだ出しませんが、汎用クラスを組み合わせて画面を組み立てる、という発想自体はここで体験しておきます）。

### BEMという命名規則

汎用クラスとは別の流れとして、「1つのパーツの中の、どの部分か」が名前から分かるようにする**BEM**という命名規則もよく使われます。単語を`__`や`--`でつなぐのが特徴です。

```html
<div class="card">
  <h3 class="card__title">サービス名</h3>
  <p class="card__text">説明文</p>
  <button class="card__button card__button--primary">詳細を見る</button>
</div>
```

- `card` — Block（パーツ全体）
- `card__title` — Element（Blockの中の部品。`__`でつなぐ）
- `card__button--primary` — Modifier（見た目のバリエーション。`--`でつなぐ）

名前を見ただけで「これは`card`の中の`title`だ」と分かるのがBEMの利点です。

### 現状はどちらが主流か

現在の実務では、BootstrapのようなCSSフレームワークが用意している汎用クラスを組み合わせて画面を組み立て、フレームワークにない部分だけ独自のclassを足す、というスタイルが主流になっています。BEMのような厳密な命名規則は、大規模で独自のデザインシステムを持つプロジェクトなどで今も使われますが、まずは「意味のある名前をつけつつ、使い回せる単位でclassを切る」という考え方を持っておけば十分です。次回、実際にBootstrapを使いながらこの感覚を掴んでいきます。
