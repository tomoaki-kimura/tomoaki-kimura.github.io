## {{ page.section_title }}

### bundle install でまとめてインストールする

前回作ったGemfileに書いたgemを、まとめてインストールします。

```bash
sample_gems $ bundle install
Fetching gem metadata from https://rubygems.org/.
Resolving dependencies...
Bundle complete! 1 Gemfile dependency, 1 gem now installed.
```

Gemfileに書いたgem（と、それが依存している他のgem）が、まとめてインストールされます。

### Gemfile.lockが作られる

`bundle install` を実行すると、`Gemfile.lock` というファイルが自動的に作られます。

```bash
sample_gems $ cat Gemfile.lock
GEM
  remote: https://rubygems.org/
  specs:
    rake (13.x.x)

PLATFORMS
  ...

DEPENDENCIES
  rake

BUNDLED WITH
   2.x.x
```

Gemfileには `gem "rake"` としかバージョンを指定していませんでしたが、Gemfile.lockには「実際にインストールされた正確なバージョン」が記録されています。

### なぜGemfile.lockが必要なのか

Gemfileだけだと、`bundle install` を実行するタイミングによって、微妙に違うバージョンのgemが入ってしまう可能性があります。Gemfile.lockを一緒にリポジトリへ含めておくことで、他の人が同じプロジェクトを `bundle install` したときも、まったく同じバージョンの組み合わせを再現できます。これはRuby自体のバージョンを揃える `.tool-versions`（asdf）と、よく似た役割です。

### bundle exec で実行する

Gemfileで管理しているgemを使ってコマンドを実行するときは、`bundle exec` をつけます。

```bash
sample_gems $ bundle exec rake hello
```

`bundle exec` をつけることで、「今このPCに入っているgemの最新版」ではなく、「Gemfile.lockに記録された、このプロジェクト用のバージョン」が使われます。

#### *ここで試したいこと

- `bundle exec` をつけずに同じコマンドを実行した場合と、結果がどう違うか（あるいは同じか）を確認してみよう。
