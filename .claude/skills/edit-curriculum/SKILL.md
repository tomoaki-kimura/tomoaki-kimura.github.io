# 既存カリキュラムの修正

このリポジトリの投稿ファイルは、対象特定を誤ったり整合性を崩したりしやすい構造なので、
**編集前に対象と影響範囲を確認してから**手を動かす。

## 1. 対象ファイルを特定する

依頼が「シューティングの3章目」のように曖昧な場合は、まず候補を検索する。

```bash
grep -rl "シューティング\|shooting" articles/_posts --include="*.md"
```

- 候補が複数ある場合は、パス・`section`・`section_title`・冒頭の`description`を提示してユーザーに選んでもらう。
- 「Ruby2D(1)のシューティング24番」のように一意に特定できる場合はそのまま進めてよい。

## 2. 変更の種類を判断する

### A. 単一ファイル内の文言・コード例の修正

- 該当箇所を読み、変更内容を簡潔に要約してから編集する。
- 依頼がすでに変更後の文言そのものを含んでいて曖昧さが無い場合は、要約確認をスキップして直接反映してよい。

### B. 複数ファイルにまたがる修正（必ず事前に計画を提示して確認を取る）

以下はこのリポジトリ特有の落とし穴。見落とすとサイトの表示が壊れる。

- **チャプターのタイトル変更**（例:「ブロック崩し」→別名）
  `title:` はそのチャプター配下の**全ファイル**で同じ値を共有している。
  変更する場合は、
  1. `articles/_posts/{part}/{chapter}/*.md` の全ファイルの `title:`
  2. `_config.yml` の該当 `contents: - title:` エントリ
  の両方を揃えて更新する。

- **パートのタイトル変更**（例:「Ruby2D(1)」→別名）
  `part:` はそのパート配下の**全チャプター・全ファイル**で共有している。
  1. `articles/_posts/{part}/**/*.md` 全ファイルの `part:`
  2. `_config.yml` の該当パートの `title:`
  の両方を揃えて更新する。

- **セクションの挿入・削除・並べ替え**
  表示順は `section:` の数値ではなく、**投稿ファイルの日付**（ファイル名の`YYYY-MM-DD`、`_includes/posts.html`の`site.posts | sort`）で決まる。
  `section:` は表からラベルとして見えているだけで、並び順そのものには使われていない。
  そのため途中に1件挿入・削除・並べ替えする場合は、
  1. 影響を受ける全ファイルの日付（＝ファイル名の日付部分）を、意図した表示順になるよう詰め直す
  2. 同時に `section:` の値とファイル名の `_NN` 連番も、表示順と一致するよう振り直す
  必要がある。対象ファイル一覧と新旧の日付/番号の対応表を作ってユーザーに提示し、確認を取ってから一括変更する。

- **`chapter:` フィールド**
  既存データでは常に `1` になっており、フォルダ内の連番ではない（用途不明の固定値）。
  意味を推測して勝手に変更しない。変更が必要そうに見えたら、まずユーザーに確認する。

## 3. 適用と確認

- 変更後、`bundle exec jekyll serve` 等でメニュー・表示順・リンクが崩れていないか確認するようユーザーに促す。
- 新規カリキュラムの追加そのものは対象外。追加は Skill `add-curriculum` を使う。
